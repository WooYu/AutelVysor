# 体验与性能检查（2026-10-22）

范围：基于 v0.10.4 / main `fb70eba`，检查 ADB 进程通信、嵌入投屏生命周期、调试窗口、Logcat 和设备轮询。未连接真机，不能据此宣称实际帧率、端到端输入延迟、CPU/内存长期占用或全部功能验收通过。

## 本轮修复

| 优先级 | 问题与根因 | 修改与验证依据 |
| --- | --- | --- |
| P1 | 大文本命令可能卡住：父进程先写完 stdin 才读 stdout/stderr，双方输出管道满时相互等待；stdin 阶段取消未进入原退出清理路径 | 同时读取两路输出后再输入；异常/取消都终止并等待子进程，保留原异常。真实子进程各传输 1 MiB stdin/stdout/stderr；用独占文件锁验证取消后的进程退出。 |
| P1 | 关闭嵌入投屏会白等：无顶层主窗口时 `CloseMainWindow()` 返回 false，仍然同步等待 1200ms | 仅成功发送关闭请求才给优雅退出等待期。无窗口子进程用例检查停止耗时低于 1 秒并实际退出；这不是手机性能基准。 |
| P1 | Logcat 的 PID/Tag/级别筛选失效，日志突发时一次 TextBox 更新过大 | 修正 threadtime 正则并预编译；组合筛选与最低级别生效；每次 UI 刷新最多 32,768 个 UTF-16 字符，同时保留原 500 行上限。单行显示最多 16,000 字符，截断有标记。验证有效/无效筛选、100 条 4K 日志分批输出且不丢失顺序，以及超长单行。磁盘导出通道不受显示截断影响。 |
| P2 | 一次应用详情刷新启动三次 `dumpsys package`，既浪费设备资源也可能得到不一致快照 | 信息、权限、原始输出共用一次快照，PID 并行读取。正常 pidof 路径从 4 个 ADB 子进程降至 2 个，package dump 从 3 次降至 1 次。测试同时校验命令次数和三个视图的数据。不能将请求数降低直接当作耗时同比降低。 |

## 后续排查清单（代码风险，尚未做真机性能复现）

- **设备轮询的长尾阻塞**：主监控串行等待无线重连及各投屏会话检查，常规 ADB 探测未统一设置超时。慢设备可能拖延其他设备的状态刷新。下一步应以可控慢 ADB 复现，并为探测设置独立超时、退出取消和有限并发，避免影响有意运行的长命令。
- **历史截图页的 UI 同步 I/O**：目录枚举和图片解码仍在 UI 线程。大量文件、重定向到网络盘的 Pictures/Videos 目录可能造成停顿。需覆盖异步枚举、预览取消和快速切换后的过期结果保护。
- **Logcat 快照的内存峰值**：快照先读取整份 logcat 输出再在主机端保留末尾行；日志量大时仍有额外内存开销。需验证 Android 4.4+ 的设备端尾部读取兼容性与失败回退，再替换现有路径。
- **长期负载实测**：需在授权 Windows 电脑与真实 USB/Wi-Fi 设备上分别测量单设备/多设备、持续高日志量、反复关闭重开、锁屏断线恢复的 UI 响应、帧率、进程句柄和内存曲线。本轮模拟测试不能替代这些结果。
